# Gemstorm 3D: Crystal Cascade

A Unity WebGL build served from GitHub Pages as part of
[Little Joy Arcade](https://littlejoyarcade.site).

- **Play:** <https://jd4rider.github.io/gemstorm-3d-web/play/>
- **Cover page:** <https://jd4rider.github.io/gemstorm-3d-web/>

## What is in here

```text
build/WebGL/                the untouched Unity WebGL export (~58 MB, uncompressed)
public/arcade-client.js     the canonical Little Joy Arcade client, copied verbatim
public/arcade-unity.js      the Unity <-> page bridge shim (save, sign-in status, achievements)
scripts/prepare-site.mjs    turns the export into a Pages-servable site and injects the account tags
site/                       generated by the script, not committed
.github/workflows/pages.yml prepare + deploy on every push to main
arcade-manifest.json        the catalogue entry for littlejoyarcade.site
```

There is no bundler, no framework and no dependencies. The only build step is
`node scripts/prepare-site.mjs`, which needs nothing but Node.

The Unity project lives separately; this repo only holds the export. To refresh it, build
WebGL in the Unity project (its build script writes straight to
`Deploy/build/WebGL/`) and copy that folder here.

## Why there is a build step at all

**Compression.** Unity's default export Brotli-compresses the payload (`*.data.br`,
`*.wasm.br`, `*.framework.js.br`) and expects the server to answer with
`Content-Encoding: br`. Pages serves files verbatim and lets you set no response headers,
so the browser would hand raw Brotli bytes to the loader and the game would stop at the
progress bar. This export ships uncompressed files; the script expands any `.br` payload it
finds and points `index.html` at the plain names, so a future compressed export still
deploys.

**Layout.** The stock Unity template pins a fixed 960×600 play area and stretches the canvas
on phones. Gemstorm reframes its own board to whatever canvas it is given
(`GameController.Reframe`), so the script replaces both template branches with one
fill-the-window rule and lets the game do the framing.

**Accounts.** `public/arcade-unity.js` and `public/arcade-client.js` are copied next to the
build and their two tags injected before `</body>`, shim first. This is the step a Unity
re-export silently undoes — a regenerated `index.html` boots the game but drops sign-in and
cloud saves — so `prepare-site.mjs` and the CI workflow both assert that both files exist
and both tags are present, in that order. `arcade-client.js` must stay byte-identical to the
platform copy; do not fork it.

## Local check

```bash
node scripts/prepare-site.mjs
python3 -m http.server 8000 --directory site   # http://127.0.0.1:8000/play/
```

## Limits worth knowing

- The page loads ~58 MB of WebGL payload on first visit; later visits are cached by the
  browser.
- There are no stars in this version, so the `three_stars` achievement is not wired. The
  game unlocks `first_clear` and `completionist`.
- `arcade-client.js` shows a 42 px account pill in the bottom-left. The game keeps that
  corner clear; the board HUD uses the top and bottom-right.
